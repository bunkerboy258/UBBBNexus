# Data Blackboard Law

本 Law 规定项目内所有运行时数据黑板的构造方式

## 领域

领域是某个特定功能模块的逻辑处理 数据集合的代称

## 逻辑处理器

逻辑处理器是负责维护领域数据的对象 一般对应 `XXXProcessor.cpp`

## 自定义数据结构 O

- O 表示领域内的自定义数据结构 与单字段同级
- 每个 O 必须独占一个 `.h` 文件
- O 所在文件只能定义这个 O
- O 禁止被单独构造 只能由所属 A 直接构造并持有
- O 直接以定义的类型命名

## 状态数据结构 A

A 表示领域内具有独立读取需求 写入责任 生命周期或清理规则的一组持久状态

- 每个 A 必须独占一个 `.h` 文件
- A 所在文件只能定义这个 A
- A 必须以 `State` 作为命名后缀
- A 禁止被单独构造 只能由所属 B 直接构造并持有
- A 的每个字段必须根据上下文使用简体中文注释
- 仅当字段具有独立生命周期 独立写入者 独立读取者 或必须形成反射及容器边界时才允许保留一至两个字段的 A
- 不满足独立状态条件的数据必须合并到语义最接近且生命周期一致的 A

## 状态持有者 B

B 是所属领域全部 A 的唯一直接持有者

- B 必须独占一个 `.h` 文件
- B 必须以 `DomainState` 作为命名后缀
- B 必须直接私有持有所属领域全部 A
- B 的数据成员只能是 A 禁止持有普通字段 C 或 D
- B 每持有一个 A 必须提供一个对应的公开只读方法
- 读取方法统一使用 `Read` 加 A 的完整类型语义命名并返回 `const` 引用
- B 除 A 对应读取方法和必要的 `friend` 声明外禁止拥有其它成员
- 负责维护 A 的逻辑处理器必须由 B 显式声明为 `friend`
- 领域外对象只能通过 B 的只读方法访问 A
- 禁止在 B 与具体 A 之间增加总 State 聚合层
- 禁止让某个 A 代替 B 汇总 转发或持有其它状态

## 状态持有者的聚合黑板 C

C 是全部 B 的唯一直接持有者

- C 必须以 `RuntimeData` 作为命名后缀
- C 公开持有全部 B
- C 的数据成员只能是 B 禁止直接持有 A D 或普通状态字段
- C 禁止增加领域逻辑 状态转发方法或清理方法
- 内层 B 禁止调用外部对象
- 运行时实例只能公开持有唯一的 C


## 临时数据 D

D 表示逻辑处理器需要分步组装后提交的暂存数据或一次调用内共享的临时数据

- D 必须以 `Context` 作为命名后缀
- D 必须放在所属领域 Law 规定的目录
- D 只能由所属领域的根调度对象在栈上临时构造
- D 用完立即销毁 禁止放入 C 跨帧保存
- D 的字段全部公开
- D 只能拥有数据 禁止增加领域逻辑
- 普通局部值 循环变量和函数参数不属于 D
- 禁止为了形式统一增加无意义的 D

## 访问路径

- 领域逻辑处理器必须通过 C 到 B 到 A 的路径获取持久状态
- C 到 B 到 A 是唯一持有链 禁止增加 B 到总 A 到具体 A 的中间层
- A B C 都是纯数据容器 清理和维护必须由具有写权限的逻辑处理器完成
- 正确结构

```text
C
└─ B
   ├─ A1
   ├─ A2
   └─ A3
```

## 生命周期

- C 的生命周期由运行时实例维护并与运行时实例保持一致
- B 的生命周期由 C 维护
- A 的生命周期由所属 B 维护
