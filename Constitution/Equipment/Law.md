# Equipment Architecture Law

严格遵守 `Constitution/Data/Law.md` 的约定

## 实例与职责

- 具体装备演员本身就是唯一运行时根 禁止另建同义的 Instance Runtime 或 Signature 对象
- 装备与角色共享清晰的输入边界与数据持有规则 不要求复制角色的系统数量与管线结构
- 抽象装备基座只提供公共组件 配置引用 动画实例引用 身份与固定输入入口
- 具体装备自主更新 角色不得代替装备 Tick 或实现具体武器的弹药与射击规则
- 装备的创建 持有 切换 附着 分离与销毁由角色侧管理 装备不得反向控制持有者的装备生命周期

## 数据与行为

- 唯一黑板按 RuntimeData 到 DomainState 到 State 直接持有 禁止把字段或待解析输入留在黑板外充当第二套状态
- 状态只能由 DomainState 直接构造并私有持有 外部通过 Read 只读访问
- 配置描述静态资源与参数 黑板保存实例事实 输入包定义具体通过条件与应用效果
- 输入先进入固定存储 再在具体装备的固定更新时机解析 禁止在提交入口立即执行动作
- 输入使用编译期具体类型与源码顺序 不为现有需求另建动态注册表 委托调度器或通用能力框架
- Context 只承载一次调用的数据 禁止持有表现方法 状态修改方法或跨帧职责
- 复用的具体操作放入有明确职责的处理器 禁止把 Context 当作服务对象

## 跨领域边界

- 角色只依赖抽象装备的固定入口 具体武器规则留在具体装备目录
- 装备向角色贡献的动作事实 蒙太奇与相机包由角色定义 只能通过角色输入入口提交
- 装备不得直接修改角色黑板 角色网络组件或玩家控制器
- 装备只识别是否镜像 禁止出现权威端 客户端 RPC 复制与预测语义
- 非镜像路径产生动作事实 镜像路径只消费已成立事实并还原 禁止重复生成弹丸等玩法结果或反向回报同一事实
- 网络观察和传输由角色网络边界负责 不进入装备内部

## 动画与时序

- 具体装备直接重写 Tick 禁止新增只为转发而存在的装备 Tick 包装层
- 装备游戏线程更新必须通过 Tick 分组与依赖等待角色更新和所需骨骼网格动画完成
- 角色的 Linked Anim Layer 与装备网格的动画实例是两个对象 禁止混为共享实例
- 角色蒙太奇通过角色输入贡献 装备自身蒙太奇在自己的动画实例播放
- 动画实例只读取已经整理的基本事实快照 不承担弹药裁决与输入解析
- 动画通知只提交输入 不能直接写装备状态或产生第二条执行管线
- 配置不匹配 身份不匹配 输入非法或固定容量耗尽等关键边界必须有明确报警
