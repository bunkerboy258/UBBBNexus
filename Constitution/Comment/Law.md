# Comment Law

## 编辑限制与适用范围

- 禁止更新任何已有注释 以下要求仅对新增注释生效
- Law 文档也算注释的一种

## 命名与说明语言

- 程序识别用稳定的英文名称 人阅读用准确的中文名称 说明负责解释单位 空间 含义与作用边界
- 注释必须使用简体中文

## 声明文档注释

- 类 函数 枚举值以及重要成员声明的文档注释一律采用 `/** ... */` 形式
- 多行文档注释中 `/**` 与 `*/` 必须独占一行 正文每行以 `*` 开头
- 公共 API 必须包含 `@param` 与 `@return` 标签 参数描述用 Tab 对齐到同一列
- 简短的 getter 可以写成单行 `/** @return ... */`

## 实现与行内注释

- `.cpp` 实现处不要重复头文件中已有的文档注释
- 逻辑性行内注释必须独占一行 写在被注释代码的正上方并保持相同缩进
- 行尾注释只允许用于补充单行语义 例如 Slate 属性链上的说明
- 注释内容首字前不要加多余空格 短句结尾不加句号

## 待办与提醒

- 待办事项统一写成 `// TODO: 描述` 禁止使用 `FIXME`
- 需要特别注意的地方写成 `// NOTE: 描述`

## 接口分组与分隔

- 接口重写的分组用 `//~ Begin X Interface` 与 `//~ End X Interface` 配对标注
- 大区块之间用 `////` 分隔条隔开
- `.cpp` 中函数与函数之间可用 `//------------------------------------------------------------------------------` 横线分隔

## 弃用与临时禁用

- 弃用接口统一使用 `UE_DEPRECATED(版本号, "完整说明")` 紧贴声明上方书写
- 临时禁用的代码必须用 `#if 0 ... #endif` 包裹 并在同行或块内注释说明禁用原因
- 禁止保留逐行注释掉的死代码
