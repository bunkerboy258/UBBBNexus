# Character Item System Law

本系统同时受角色系统 Law 与数据宪法约束。

## 职责
- 本系统拥有真实物品定义 物品实例登记 物品位置与前序主手选择语义。
- 武器 穿戴品和杂物均是物品。
- 穿戴品与杂物不要求 Actor 武器的内部玩法由其装备 Actor 维护。
- 本系统不得引用 AppearanceSystem 的类型 不知道模型 材质 贴片与人物组装规则。
- 本轮不实现堆叠 消耗品 地面拾取 丢弃或背包持久化。

## 物品存储与位置
- 角色只有一份真实物品槽位数组 前序为背包 后序为穿戴物品栏。
- 每件实例只有一个稳定身份 且只登记在一个位置。
- 穿戴后释放原背包格子 不复制物品。
- 位置许可由本系统的静态物品位置语义决定 不解释显示资源。
- 所有位置共享转移与交换机制 交换前必须同时检查双方位置许可。
- 获得物品仅放入首个可用背包空格子 不自动选中或穿戴。
- 脱下时移入指定背包格子 未指定时寻找空格子 满包且不能合法交换时拒绝。
- 失败不得丢失物品 不得产生部分交换。
- 物品背包暂不改变背包容量。
- 背包与穿戴格子计数分开 穿戴位置不增加背包容量。

## 主手选择
- 前序快捷格子是背包的上层语义 不创建另一份容器。
- 只有主动装备能成为主手目标。
- 主动选择装有穿戴品或杂物的快捷格子拒绝 并保留原有效选择。
- 选中格子变空 物品失效或被换为非装备时生成空手目标。
- 重复选择有效装备不执行收起 手持目标跟随格子内容。
- 先完成物品位置操作 再生成本帧主手结果。

## 系统与实例边界
- 实例登记 创建及最终销毁由本系统对应处理器维护。
- EquipmentSystem 只读主手结果 AppearanceSystem 只读物品位置结果。
- 本系统不得调用这两个系统 这两个系统不得反向修改物品领域。
- 角色关闭时先解除使用与显示关系 再清理真实物品。
- Mirror 不创建真实物品 不填充背包或穿戴格子。

## 输入与网络
- 外部请求只通过角色 SubmitInput 输入包位于 Character/Input/LocalControl/Item/。
- 输入包仅发布待消费操作 处理器决定操作是否成立。
- 同帧带数据请求必须累计 不得静默覆盖。
- 本系统不得持有 RPC 复制版本或具体网络业务。
- UI 只读公开状态并提交输入 禁止直接改黑板。

## 物理目录
- 严格遵守 ../Law.md 的系统根 DomainData States Definitions Context 与 Processors 结构。
- 静态物品定义属于 Character/Config/Item/ 统一注册入口位于 Item/Catalog/。
- 禁止保留旧装备专用获取路径 旧 Actor 背包入口或兼容转发。
