# Character Item System Law

本系统同时受角色系统 Law 与数据宪法约束.

## 职责
- 本系统包装外侧物品定义 维护物品实例登记 物品位置与前序主手选择语义.
- 装备 穿戴物 消耗品和杂物均是物品.
- 穿戴物与杂物不要求 Actor 装备和消耗品的内部状态由其各自内部逻辑维护
- 本系统不得引用 AppearanceSystem 的类型 不知道模型 材质 贴片与人物组装规则.

## 物品存储与位置
- 角色只有一份真实物品槽位数组 前序为背包 后序为穿戴物品栏.
- 每件实例只有一个稳定身份 且只登记在一个位置.
- 穿戴后释放原背包格子 不复制物品.
- 位置许可由本系统的静态物品位置语义决定 不解释显示资源.
- 所有位置共享转移与交换机制 交换前必须同时检查双方位置许可.
- 获得物品先补同型号堆叠 再按所属类别寻找空格 整次数量不能放下则拒绝 不部分接受 不自动穿戴.
- 脱下时移入指定背包格子 未指定时寻找空格子 满包且不能合法交换时拒绝.
- 失败不得丢失物品 不得产生部分交换.
- 物品背包暂不改变背包容量.
- 背包与穿戴格子计数分开 穿戴位置不增加背包容量.

## 主手选择
- 前序快捷格子是背包的上层语义 不创建另一份容器.
- 只有装备成为持续主手目标 消耗品快捷选择产生独立使用目标 不替换当前装备主手目标
- 装备选择和消耗品选择分开约束
- 主动选择装有穿戴品或杂物的快捷格子拒绝 并保留原有效选择.
- 装备选中格子变空 物品失效或被换为不可持有类别时生成空手目标
- 消耗品耗尽不得把仍然有效的装备改成空手
- 重复选择有效装备不执行收起 手持目标跟随格子内容.
- 先完成物品位置操作 再分别生成本帧装备主手结果与消耗品使用选择结果

## 系统与实例边界
- 实例登记 创建及最终销毁由本系统对应处理器维护.
- InteractionSystem 分别只读装备主手结果与消耗品使用选择结果 不反向修改 ItemSystem 状态
- AppearanceSystem 只读物品位置结果
- 本系统不得调用这两个系统 这两个系统不得反向修改物品领域.
- 角色关闭时先解除使用与显示关系 再清理真实物品.
- Mirror 不创建真实物品 不填充背包或穿戴格子.

## 输入与网络
- 外部请求只通过角色 SubmitInput 输入包位于 Character/Input/LocalControl/Item/.
- 输入包仅发布待消费操作 处理器决定操作是否成立.
- 同帧带数据请求必须累计 不得静默覆盖.
- 本系统不得持有 RPC 复制版本或具体网络业务.
- UI 只读公开状态并提交输入 禁止直接改黑板.

## 物理目录
- 系统根采用 DomainData States Definitions Context 与 Processors 结构.
- 静态物品定义与四类注册入口属于外侧 Item/ 角色文件与类型使用 CharacterItem 命名.
- 禁止保留旧装备专用获取路径 旧 Actor 背包入口或兼容转发.

## 堆叠与消耗品
- 数量由本系统唯一维护 同型号可合并 整组可移动或交换 本轮不提供手动拆分.
- 装备二十格 穿戴物二十格 消耗品三十格 杂物三十格
- 装备保留现有五格快捷位置 消耗品五格固定为两个投掷位置和三个恢复位置 仍包含在现有消耗品容量内
- 消耗品只能使用 不存在持续持有状态 所有网格显示都通过通知生成
- 使用成功后通过通用数量输入扣减 完成通知通过角色输入解除使用占用 本系统不解释物品使用步骤
- 使用期间保留装备关系 完成后解除使用占用和临时显示关系
- 零数量实例先保留至动作结束并解除持有 再由本系统最终销毁 不销毁已投出的实体.
- 使用中拒绝背包操作和主动切换 通过阻碍物品相关输入包实现 冲突动作中的快速使用直接拒绝 不排队延迟执行
