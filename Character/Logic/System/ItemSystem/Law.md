# Character Item System Law

本系统同时受角色系统 Law 与数据宪法约束。

## 职责
- 本系统负责角色真实背包的维护 以及背包上层的物品栏选择语义。
- 背包存储与物品栏选择必须由不同职责的处理器维护。
- 本系统禁止持有具体武器的开火 换弹 弹药 动画或网络业务。
- 本轮只支持现有武器与装备 不实现堆叠 消耗品 地面拾取与丢弃。

## 背包存储
- 角色只有一份背包槽位数组。
- 所有槽位使用相同的数据结构与操作规则。
- 背包槽位本身没有主手 快捷栏或普通格子的类型区别。
- 禁止维护独立物品栏数组 快捷绑定表或第二份物品容器。
- 每件物品占用一个槽位 同一物品实例不得在多个槽位中重复登记。
- 同型号装备可以拥有多个独立实例 各自状态由对应装备实例维护。
- 背包处理器只维护物品存储 不判断快捷作用 不决定角色装备。
- 获得物品时放入首个可用空槽位 背包已满则拒绝新增。
- 获得物品只入包 不改变物品栏选择与当前手持装备。
- 移动到空槽位时转移物品 移动到已占用槽位时交换内容。
- 非法操作与失败操作不得丢失物品或破坏原有槽位内容。
- 无效物品引用的清理由背包处理器维护。

## 物品栏上层语义
- 物品栏处理器读取同一份背包的前若干槽位。
- 前序槽位的快捷与主手作用由物品栏处理器赋予 不写入背包槽位类型。
- 快捷槽位数量不得超过背包总容量。
- 本轮只将前序快捷槽位映射到主手装备选择 禁止为其它能力创建占位机制。
- 后序槽位不能直接被选中作为主手装备槽位。
- 物品栏处理器维护选中槽位 并生成该槽位对应的目标主手物品结果。
- 手持目标跟随选中槽位的内容 不跟随被移动的物品实例。
- 重复选择当前有效槽位保持当前选择 不执行收起。
- 主动选择空槽位 或选中槽位变空 物品失效时 取消选择并生成空手目标。
- 取消选择后 物品进入原槽位不会自动恢复选择或自动装备。
- 背包操作完成后再维护物品栏选择 保证本帧目标对应本帧槽位内容。

## 实例与系统边界
- 真实背包物品实例的创建 登记及最终销毁由本系统对应处理器维护。
- 物品实例负责自身初始化 内部玩法与内部清理。
- EquipmentSystem 只读本系统生成的目标主手物品结果。
- 本系统不得调用 EquipmentSystem 或其处理器执行装备操作。
- EquipmentSystem 不得反向写入背包 选中槽位或物品栏目标。
- 角色结束运行时 先解除装备使用关系 再销毁真实背包物品实例。

## 输入与对外访问
- 外部物品操作统一通过角色 SubmitInput 提交。
- 物品操作与快捷选择输入定义在 Character/Input/LocalControl/Item/。
- ParseSystem 只解析输入包并写入对应输入状态 具体操作由本系统处理器完成。
- 同帧输入处理遵守 Actor Law 不得静默丢失携带数据的物品操作。
- 背包及物品栏状态对领域外保持只读。
- 玩家 UI 读取公开结果并提交输入 不直接修改黑板 不执行物品或装备逻辑。

## 执行与网络边界
- 真实背包及快捷选择由控制该角色的客户端维护。
- 镜像角色不根据还原的手持装备生成或填充真实背包。
- 本轮不新增背包网络同步。
- 持有关系同步与具体装备状态同步沿用各自现有职责。
- 本系统不得持有 RPC 复制版本或其它具体网络逻辑。

## 物理目录
- 系统根 DomainData States Definitions Context 与 Processors 严格遵守 ../Law.md 的目录和数据构造规则。
- 背包状态 物品定义与物品栏选择状态统一归属本系统。
- 禁止保留 EquipmentSystem 中的旧容器状态 旧快捷选择状态 转发入口或兼容路径。
