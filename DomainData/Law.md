# Domain Data Construction Law

本 Law 是 `Character/` 与 `Equipment/` 的附属规则，约束领域数据的声明、组装、写权限和生命周期。

## 声明与依赖

- 头文件只在指针、引用、函数参数或返回值场景使用前向声明；按值成员、继承、模板实例化和 UHT 需要完整类型时必须包含定义。
- 完整实现依赖优先放入 `.cpp`，禁止为了省事在公共头文件包含领域聚合头或具体实例头。
- 前向声明必须位于最小可见作用域，禁止声明与引擎或项目真实类型不一致的 `class/struct`。

## 所有权与组装

- 每份跨帧 State 必须有唯一拥有者；角色数据由角色运行时根持有，装备实例数据由对应静态 Runtime 持有。
- 固定输入和跨帧 State 优先按值驻留；只在共享 UE 对象生命周期时保存 `TObjectPtr`，禁止裸 `new/delete` 管理领域数据。
- `Initialize` 只注入必需依赖和初始值，统一由所属 Core Initializer 或实例生命周期入口调用；`Update` 禁止惰性创建依赖或自行搜索替代对象。
- 保存的裸指针与引用一律视为非拥有关系，其有效期必须由上层拥有者覆盖使用期；临时 Context 必须在栈上构造并只在本次调用中使用。

## 写权限与友元

- 跨帧 State 的可写对象必须封闭在拥有者内部；对外只提供 `const` 读取或只读 getter。
- State 字段可以作为静态签名使用的普通聚合数据，但非 `const` State 只能交给明确的唯一写入签名、Controller、System 或 Processor。
- 私有构造、初始化、清理和写入接口只能授予实际负责该阶段的精确 `friend class/struct`，禁止宽泛友元、传递友元和仅为省略 API 而增加友元。
- 输入包与单帧 Context 可以公开数据字段，但不得借此保存跨帧可写状态、拥有对象生命周期或绕过领域写入口。

## 维护与生命周期

- 组装者负责建立依赖，领域拥有者负责日常维护，主管线负责调用时序，Shutdown 或装备生命周期入口负责按组装反序解除关系。
- 创建、初始化、更新、清理和销毁的责任必须各有唯一入口，禁止同一数据由多个系统竞争初始化或清理。
- UObject、Actor 和 Component 的销毁继续交给 UE 所有权体系；领域代码只解除自己建立的 Tick、附着、动画和引用关系。
- 必需依赖缺失必须在组装边界使用 `ensureMsgf` 报警并拒绝进入半初始化状态，普通运行时条件不满足则安全返回。
